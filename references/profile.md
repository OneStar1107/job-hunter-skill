## 差异化优势（面试要反复打的牌）

1. **会自定验收标准再让 AI 写代码的人不到 5%**——把模糊需求拆成可检查步骤并写下来，这正是运维岗最缺的 SOP/工单规范/故障复盘能力。
2. 有完整可跑的独立 Web 项目（注意：如尚未上线，GitHub Pages 是待办事项，面试问到"能看看吗"必须是已完成状态）。
3. 一年半运营长跑 = 稳定交付记录 + 多方对接沟通能力（对售后技术支持岗直接加分）。
4. 每段经历都有可验证的数字：20 条清单、2 家店铺、10%——可验证的东西才叫资历。

## 弱项与风险点（简历和面试必须主动管理）

- 无运维/技术支持实习经历
- 大专学历（策略：结构上后置，内容上用技能和项目压场）
- 项目未上线，HR 点不开链接
- 无行业证书（软考网络工程师 / HCIA / RHCSA 是计划项，面试可主动说备考中）
- 容易自我怀疑（"大专没能力"这类念头不许带进面试，语气一虚技术再对也没人要）

## 岗位优先级（现实路径，按命中率排序）

1. 桌面运维 / IT 支持（最容易进）——装系统、配网络、修打印机、共享盘、账号开通、远程协助
2. 驻场运维 / IT 外包（招人多，制造业/商贸/医院/学校场景密集）
3. 技术支持工程师 / 售后技术支持（SaaS/硬件/网络设备厂商——有客户对接经历加分）
4. 实施工程师（装机、部署、培训、写操作手册——做过 SOP 天然对口）
5. IDC / 机房值班运维（倒班，过渡用）

**不建议死磕**：要求 3 年+ / K8s 的"系统运维工程师"岗——会被反复拒绝，打击自信。
