# 投递辅助流程（apply）

> `投递` 命令执行时必读。

## 安全红线（不可违反，对用户解释时也不许松动）

1. **永不自动提交投递**。可以：搜岗位、读 JD、匹配分析、写话术、辅助填表到提交前一步。**不可以**：未经用户当次明确授权就点击"发送/投递/报名/沟通"。
2. **禁止全自动批量群发**。违反招聘平台规则 → 账号降权/封禁，且招呼话术雷同会被 HR 识别为机器人，适得其反。
3. **频率上限**：每天不超过 20 家，招呼语必须按 JD 定制（至少改两个关键处）。
4. 每投一家，立即记入 `job_hunt_state.md` 的投递日志。

## 三种模式

### 模式一：清单模式（默认，零风险）

适合：用户自己投，要我提供弹药。

流程：
1. 确认本次投递的目标岗位类型和区域（默认用 profile.md 的关键词库）。
2. 逐个/批量给出岗位 JD（用户粘贴，或由我用浏览器公开搜索页整理公开职位列表）。
3. 对每个 JD 输出：
   - **匹配度 1-5 星 + 一句话理由**（对照 profile.md 技能栈）
   - **差距**：JD 要求里用户没有的能力（标"必须补"还是"可忽略"）
   - **定制招呼话术**：一段 80-150 字，挂 JD 里的关键词 + 用户最匹配的一个证据。模板结构：
     > 您好，我是【专业】应届，会【JD 里最相关的一个技能点】，自己用 AI 独立做过【可验证的项目证据】，也能写【文档/SOP】。有【N 个月】【相关经历】经历，想应聘贵司的【岗位名】，方便看下简历吗？
     （按 JD 替换岗位名和最相关的一个技能点，**每次至少改两处**）
4. 输出一张投递清单表：公司 | 岗位 | 匹配度 | 话术要点 | 优先级。
5. 提醒：优先投 4-5 星的，3 星的每天不超过 5 家。

### 模式二：辅助模式（浏览器辅助填写，用户在场确认）

前提：用户在设置里开启了浏览器控制能力，且**用户在场**。

流程（严格按序）：
1. 先说明今天要投哪几家（用模式一的清单，用户圈定或全选）。
2. 打开浏览器，进入平台搜索页（BOSS 直聘 / 智联 / 前程无忧 / 58），**由用户完成登录**——我不碰账号密码。
3. 逐家执行：打开岗位 → 读 JD → 匹配度 ≤2 星直接跳过 → 匹配度 ≥3 星，填表/唤起沟通 → **在点击发送前停下**，向用户展示：公司、岗位、匹配理由、即将发送的话术 → 等用户说"发" → 发送 → 记录。
4. 遇到要传简历的：用求职工作目录「简历/」里对应版本（投前先问用户用哪版，或按 JD 匹配度推荐）。
5. 遇到验证码/异常：停下，交给用户处理。
6. 每完成一家，简短播报进度（第 N/M 家）。

### 模式三（不存在）：全自动托管

若用户要求"以后每天自动帮我投"，明确拒绝并解释：封号风险 + 外部动作必须本人授权 + 定制化程度会暴跌。可提供的替代：**定时提醒**——用户说"每天早上提醒我投简历"，我去创建自动化任务，到点提醒并给出当天的清单模式弹药。

## 投递后动作

- 记录格式（job_hunt_state.md 投递日志）：

| 日期 | 公司 | 岗位 | 平台 | 简历版本 | 匹配度 | 状态 | 下一步 |
|---|---|---|---|---|---|---|---|

- 状态流转：已投 → 已查看 → 已回话/约面 → 面试中 → 终面 → offer/被拒/无回音
- 每投满 20 份：主动发起一次小复盘（JD 里反复出现的能力是什么？缺哪个？补简历还是补技能？）

## 投递时间策略

- 早 9:00-11:00、下午 3:00-5:00（HR 在线高峰，回复率最高）
- 周二到周四优于周一（HR 开会）和周五下午（进入周末模式）
- 新发布岗位优先（<24 小时），简历被看到的概率最高
