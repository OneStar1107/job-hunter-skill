# 面试模块（运维/技术支持方向）

> `面试` 命令执行时必读。含模拟面试规则、评分体系、题库。
> 文中括号里的示例证据均指示例档案（虚构人物小陈）的数据，实际执行时替换为 profile.md 里的真实证据。

## 模拟面试规则

### 开场（只问必要信息，一次一个）

1. 格式：`技术基础问答` / `场景排障` / `行为面` / `混合（最接近真实初面）` / `压力面`。默认推荐混合。
2. 目标公司/岗位（有 JD 更好，没有就用档案里的默认目标）。
3. 难度：默认"应届初级"。用户要求"往死里问"时才上高强度。

### 执行纪律

1. **一次一题**，等回答再下一题。
2. **中途零反馈**——不点头、不纠正、不解释。像真实面试一样往下走。观察记录默默做。
3. **难度递进**：中 → 难 → 一个出其不意（追问细节、突然换场景、沉默五秒）。
4. **智能追问**（这是本模块的灵魂）：
   - 答得空泛 → "能说具体点吗？比如你实际敲了什么命令？"
   - 答得具体 → 顺藤摸瓜加深："那如果 XXX 变了呢？"
   - 出现"我们"→ "这个事里你个人负责哪部分？"
   - 说法前后矛盾 → "你刚才说 A，现在说 B，以哪个为准？"
   - 明显在背 → 换个角度问同一件事
5. **至少一题直击弱项**（档案里列出的弱项，如无实习/学历/项目未上线之一）——真实面试里这关必须过，躲不掉。
6. **技术题边界**：我评的是表达和思路（排查有没有章法、说不说得清、会不会不懂装懂）。技术细节正误标注"待核实"，不硬装权威。

### 收尾三问（评分前必问）

1. "整体感觉如何：强烈推荐 / 推荐 / 待定 / 不推荐？"
2. "答得最好的是哪题？最虚的是哪题？"
3. "重来一次你会改什么？"

**先听用户自评，再亮评分**——自评与实评的差距本身就是教学素材。

### 评分（运维版五维，各 1-5）

| 维度 | 看什么 |
|---|---|
| 技术准确性 | 命令、概念、流程对不对；不懂时是否承认并给出排查思路而非硬编 |
| 表达结构 | 有没有章法（先问清现象→再定位→再处理→再确认）；还是东一句西一句 |
| 岗位匹配 | 答案是否落在运维/技术支持的真实工作场景里 |
| 可信度 | 有证据（命令、日志、文档、数字）还是有印象流 |
| 差异化 | 有没有只有这个人能答出的东西（档案里列出的独特证据：验收清单、SOP、AI 协作、客户对接） |

## 题库

### A. 技术基础高频题（初面必考区）

**Linux**
- 常用命令过一遍：top / df -h / du -sh / ps / netstat -an / ss / systemctl / journalctl / tail -f / chmod chown / tar / rsync / crontab / vim
- 场景：服务器磁盘满了怎么查？（df -h 定位分区 → du -sh 定位目录 → 清日志/归档 → 查是谁在写）
- 场景：某个服务挂了怎么处理？（systemctl status → journalctl -u 看日志 → 重启 → 找根因 → 记录）
- 场景：忘记 root 密码 / 某个文件删了怎么恢复（无备份时）——考的是排查思路和诚实
- 问 LNMP：你在实验里具体做了哪几步？Nginx 配过什么？（必须能讲出真实细节，别背概念）

**网络**
- 用户上不了网，你的排查顺序？（本题是运维面试国粹，必须练到条件反射：问清现象→ipconfig 看有没有拿到 IP→ping 网关→ping 外网 IP→ping 域名→nslookup→换浏览器/换机器→逐层定位）
- TCP 和 UDP 区别？三次握手为什么是三次？
- DNS 解析过程？ping 通域名但打不开网页可能为什么？

**Windows**
- 打印机共享不出来怎么查？（经典桌面运维题：服务、权限、网络发现、驱动）
- 远程桌面连不上？（本机设置、防火墙、网络级别认证、账号权限）
- 组策略/共享权限/域账号概念

**数据库（初级会基础即可）**
- mysqldump 怎么备份？怎么恢复？用户授权怎么做？
- "数据库慢"你看哪里？（慢查询日志、索引、连接数——承认深度有限但知道方向）

**容器（概念级）**
- 镜像、容器、卷三个词讲清；docker run / ps / logs / exec 用过没有

### B. 场景排障题（技术支持岗的真正考题）

- "客户说系统卡，你远程过去第一步做什么？"（先问清楚：什么时候开始、所有人都卡还是一个人、卡在哪个环节——先复现和界定，再动手）
- "客户很急、语气很差，你一边排查一边怎么沟通？"（先给时间预期，再同步进展，不沉默——有客户/商家对接经历的是弹药）
- "你解决不了的问题，什么情况下升级？怎么升级？"（不丢人，丢人的是硬扛到超时）
- "客户问的这个故障你从没遇到过，怎么办？"（查知识库/工单历史 → 复现 → 找日志 → 升级，讲流程不讲运气）

### C. 行为面（STAR 结构：情境-任务-动作-结果）

- 为什么想做运维/技术支持？（不许说"稳定"，要说具体触发点+已做的准备）
- 讲一个你把混乱的事理清楚的事（→ 档案里的验收清单、信息层级设计等证据）
- 讲一个你反复失败最后搞定的事（→ 档案里迭代过两轮以上的项目）
- 和难沟通的人合作过吗（→ 档案里的多方对接经历）
- 能接受夜间/周末处理故障吗？（值班是运维常态，犹豫就输了）
- 职业规划？（3 年路径：熟悉基础设施 → 考下证书 → 能独立负责一片）

### D. 压力面（弱项管理，答案要预演到脱口而出）

- "大专学历，你觉得能胜任吗？"（承认学历是事实 → 立刻转到证据：环境是我自己搭的、项目是我独立做的、验收标准是我自己定的 → 这个岗位看的是排查和交付，我用作品说话）
- "你没有对口实习，怎么证明你能干？"（实习是经历的一种，我换成另一种方式验证自己：把每个项目当真实交付做，写文档、定验收、留记录——这正是运维日常）
- "项目能看看吗？"（上线 GitHub Pages 是待办；被问到时的标准答案是主动给本地演示+README，并说明上线计划。**别等被问才做**）
- "期望薪资低了点吧？"（第一份看成长空间，但我有独立负责多项任务并按时交付的记录，不是零基础小白）
- "你投了很多家吧？/ 为什么这么久还没入职？"（在按计划推进：每周固定投递、复盘、补短板，策略是先进企业 IT 攒真实故障经验）

### E. 反问环节（候选人问什么决定印象）

好问题示例：
- "这个岗位日常处理最高频的三类问题是什么？"
- "团队现在有文档/工单规范吗？我写过 SOP，想知道怎么融入。"
- "如果我入职，前三个月您希望我达成什么？"
雷区：一上来问加班多不多、薪资能不能谈（初面问这些直接减分）。
