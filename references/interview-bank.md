# 面试模块（通用版）

> `面试` 命令执行时必读。含模拟面试规则、评分体系、题库。
> 文中括号里的示例证据均指示例档案（虚构人物小陈）的数据，实际执行时替换为 profile.md 里的真实证据。

## 模拟面试规则

### 开场（只问必要信息，一次一个）

1. 格式：`基础问答` / `场景应变` / `行为面` / `混合（最接近真实初面）` / `压力面`。默认推荐混合。
2. 目标公司/岗位（有 JD 更好，没有就用档案里的默认目标）。
3. 难度：默认"应届初级"。用户要求"往死里问"时才上高强度。

### 执行纪律

1. **一次一题**，等回答再下一题。
2. **中途零反馈**——不点头、不纠正、不解释。像真实面试一样往下走。观察记录默默做。
3. **难度递进**：中 → 难 → 一个出其不意（追问细节、突然换场景、沉默五秒）。
4. **智能追问**（这是本模块的灵魂）：
   - 答得空泛 → "能说具体点吗？比如你实际做了什么动作？"
   - 答得具体 → 顺藤摸瓜加深："那如果 XXX 变了呢？"
   - 出现"我们"→ "这个事里你个人负责哪部分？"
   - 说法前后矛盾 → "你刚才说 A，现在说 B，以哪个为准？"
   - 明显在背 → 换个角度问同一件事
5. **至少一题直击弱项**（档案里列出的弱项，如无对口实习/学历专业不对口/项目未上线之一）——真实面试里这关必须过，躲不掉。
6. **专业题边界**：我评的是表达和思路（有没有章法、说不说得清、会不会不懂装懂）。专业细节正误标注"待核实"，不硬装权威。

### 收尾三问（评分前必问）

1. "整体感觉如何：强烈推荐 / 推荐 / 待定 / 不推荐？"
2. "答得最好的是哪题？最虚的是哪题？"
3. "重来一次你会改什么？"

**先听用户自评，再亮评分**——自评与实评的差距本身就是教学素材。

### 评分（五维，各 1-5）

| 维度 | 看什么 |
|---|---|
| 内容准确性 | 概念、流程、数据对不对；不懂时是否承认并给出思路而非硬编 |
| 表达结构 | 有没有章法（先问清需求→再行动→再确认结果）；还是东一句西一句 |
| 岗位匹配 | 答案是否落在目标岗位的真实工作场景里 |
| 可信度 | 有证据（数据、文档、作品、反馈）还是有印象流 |
| 差异化 | 有没有只有这个人能答出的东西（档案里列出的独特证据：验收清单、独立项目、AI 协作、对接经历） |

## 题库

### A. 基础高频题（任何岗位初面必考）

- 自我介绍（90 秒版本：一句话定位 + 两个最相关的证据 + 为什么是这个岗位）
- 为什么想做这个岗位/这个方向？（不许说"稳定/感兴趣"，要说具体触发点 + 已做的准备）
- 你对我们公司/这个岗位有什么了解？（考投递前有没有做功课时）
- 你觉得这个岗位日常最重要的是什么？（考岗位理解，答案要落在具体工作上）
- 职业规划？（3 年路径：熟悉业务 → 独当一面 → 能带一块/负责一片）

**专业基础题按方向准备**（示例）：
- 技术岗：常用工具/命令过一遍；"某个东西出问题了你怎么查"（考排查思路）
- 运营岗："你觉得我们产品有什么可以改进的？"（考产品sense和表达）
- 职能岗："多项任务同时到期你怎么排优先级？"（考条理）

### B. 场景应变题（任何岗位都考）

- "多个任务同时到期/客户很急，你一边处理一边怎么沟通？"（先给时间预期，再同步进展，不沉默）
- "你解决不了的问题，什么情况下升级？怎么升级？"（不丢人，丢人的是硬扛到超时）
- "遇到你从没处理过的问题，怎么办？"（查资料/历史案例 → 复现 → 找数据 → 升级，讲流程不讲运气）
- "上级给了个模糊需求，你怎么下手？"（先问清目标和边界 → 拆成可检查的步骤 → 小步验证——示例档案里的验收清单方法论就是答案）

### C. 行为面（STAR 结构：情境-任务-动作-结果）

- 讲一个你把混乱的事理清楚的事（→ 档案里的验收清单、信息层级设计等证据）
- 讲一个你反复失败最后搞定的事（→ 档案里迭代过两轮以上的项目）
- 和难沟通的人合作过吗（→ 档案里的多方对接经历）
- 讲一个你用数据说服别人/改进工作的例子
- 能接受岗位的非常规作息吗（如岗位有值班/出差/旺季加班，犹豫就输了）

### D. 压力面（弱项管理，答案要预演到脱口而出）

- "学历/专业不对口，你觉得能胜任吗？"（承认是事实 → 立刻转到证据：项目是我独立做的、标准是我自己定的 → 这个岗位看的是交付，我用作品说话）
- "你没有对口实习，怎么证明你能干？"（实习是经历的一种，我换成另一种方式验证自己：把每个项目当真实交付做，写文档、定验收、留记录）
- "项目能看看吗？"（上线 GitHub Pages 是待办；被问到时的标准答案是主动给本地演示+README，并说明上线计划。**别等被问才做**）
- "期望薪资低了点吧？"（第一份看成长空间，但我有独立负责多项任务并按时交付的记录，不是零基础小白）
- "你投了很多家吧？/ 为什么这么久还没入职？"（在按计划推进：每周固定投递、复盘、补短板）

### E. 反问环节（候选人问什么决定印象）

好问题示例：
- "这个岗位日常处理最高频的三类工作是什么？"
- "团队现在有文档/流程规范吗？我整理过 SOP，想知道怎么融入。"
- "如果我入职，前三个月您希望我达成什么？"
雷区：一上来问加班多不多、薪资能不能谈（初面问这些直接减分）。

## 附录：如目标岗位偏技术，可加练的速查（示例）

Linux：`top df -h du -sh ps aux netstat -an ss -tlnp systemctl status/restart journalctl -u xxx -f tail -f chmod chown tar rsync crontab vim 基本操作`
网络排障：`ipconfig ping tracert nslookup netstat`（问清现象→看有没有拿到 IP→ping 网关→ping 外网→ping 域名→逐层定位）
数据库：`mysqldump 备份/恢复、用户授权、慢查询看一眼`
监控概念：Zabbix / Prometheus + Grafana 长什么样、干什么用（不硬吹）
